# 2026-09 工程审查与修复

基线：`5d7f99a` / 2.8.3。范围包括 Python daemon、Swift API/状态层、AppKit 生命周期、SwiftUI 界面、更新安装及本机 HTTP 边界。交付流程为本机安装验证，用户确认后再发布。

## 架构与组织

- 保留 SwiftPM、AppKit + SwiftUI、标准库 Python 与 SQLite WAL 的现有边界，不引入第三方依赖。
- 设置磁盘读取和 API 保存共用 `_clean_settings`，避免类型、范围规则分叉。
- APIClient 支持注入 URLSession，异步顺序与失败行为可以用受控响应验证。
- 会话预览请求由 SwiftUI `.task(id:)` 管理，生命周期与展开行、文件修改时间一致。
- 后端的采集、索引、HTTP 和更新安装仍位于 `agentdeckd.py`。本轮优先修复其行为边界；全面拆文件会同时改变测试 patch 路径、打包资源和子进程导入路径，应作为独立重构分阶段验证。

## 安全边界

检查现有 Host/Origin/JSON 同源校验、hook 转写路径绑定、会话 ID 和 shell/AppleScript 转义、更新源与完整包签名/Team ID/Gatekeeper 验证。自动粘贴和重定向处理也属于动作边界，不仅是 UI 行为。

测试使用临时文件与受控网络响应；真实 CLI 登录态、上游服务返回和 macOS 辅助功能授权仍需本机运行验证。审查不能证明不存在其他缺陷，也不以测试数量替代行为覆盖。

## 本机安装验证

- 已用 `./build.sh install` 构建并安装 universal 应用；完整签名校验通过，安装包内后端与工作区一致。版本保留 2.8.3，未提交、推送或发布。
- 813 个会话的真实数据集：缓存格式升级后的首次用量重建约 89.2 秒。期间 30 次健康探测实例不变，平均 55.8 毫秒、最大 248.9 毫秒；会话接口约 116 毫秒。首次重建仍是明确的等待成本，不应描述为所有统计均即时可用。
- 热缓存复测：用量 2.9 毫秒、会话 18.0 毫秒、缓存额度 2.0 毫秒；30 次健康探测平均 2.0 毫秒、最大 4.6 毫秒，无后端重启。
- 进程清单仅有一个应用及其子后端。重建完成后采样两者 CPU 均为 0%，RSS 分别约 25 MB、35 MB；这是时点采样，不代表长期资源上限。
